# Build status

## Current status
The public site and API are on Vercel project babelbeam (deployment id updated on each prod deploy). Deploys must be run from the repo root (`C:\local\BabelBeam`) so FastAPI builds; a deploy from `apps/web` omits the backend and breaks `/api`. `GET /api/v1/health` returns JSON. Provider mode is live. `PRODUCTION_BILLING_ENABLED` is false. Billing is not activated for live sales. Pilot milestones A–D are implemented in software; Milestone E device matrix remains operator-owned (`docs/10-wake-lock-and-background.md`).

Owner decision (2026-10-25): church payment model is undecided. Visible payment/pricing/trial copy is off the UI. Homepage Start Class goes straight into the live teacher class page (auto-starts; QR + join code; no interim teacher-home / billing preview). Phone-first teacher UI: top menubar question inbox badge, listener status pill, mic and End Class. AI disclaimer and headset/install hint use low-opacity legal treatment. Soft-refresh after deploy for Tom and demo users.

Owner decision (2026-10-25): teacher QR helper is a short spoken script with exact Spanish student button labels (Tu nombre, Masculino/Femenino, Entrar a la clase, Hacer una pregunta, Detener).

On join, students enter a name and tap man/woman silhouette icons (aria Male/Female or Masculino/Femenino; API boy/girl). Teacher English question playback uses Mateo-style `verse` (boy) or Valeria-style `marin` (girl).

Demo path: Start Class, show QR and join code, teach with mic or typed line. Students scan QR, join, listen, and may ask questions. Teacher question inbox (top-bar badge) and End Class remain. Say next, rehearsal, install promo, and dense marketing chrome are off the demo screens.

The site is an installable PWA, not an App Store binary. There is no separate media room. Bluetooth is not paired by the app.
